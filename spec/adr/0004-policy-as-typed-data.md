# ADR-0004: Business rules are typed, versioned policy documents (no DSL)

- Status: Accepted (2026-10-25)

## Context
The product's value is configuring a school in ≤ 3 steps. All 40 v0 rules turned out to be parameters of known mechanisms (04 §9). A rule engine or DSL would add a language for owners to learn and for maintainers to secure.

## Decision
- One Rust struct per module (`XPolicy`), with a JSON Schema generated by schemars and UI hints in `x-ui`.
- Stored append-only with versions and `effective_from`.
- Presets are JSON Merge Patches over the defaults.
- The SPA renders forms generically from the schema.

## Consequences
- ✅ A new rule field = add a struct field, a default, an i18n label and a test. No frontend work.
- ✅ Every rule change is versioned and audited, and can be scheduled for the future.
- ❌ Truly custom logic isn't expressible. Escape hatch: a new enum variant via PR, or a future `Extension` trait (v2+).
